# 0006 — CI/CD on GitHub Actions, public repository

- **Status:** Accepted
- **Date:** 2026-10-14

## Context
Every change must be verified on both platforms, and every environment must be deliverable without manual build steps,
while STAGE/PROD stay behind a human decision. The repository was created private on the owner's **GitHub Free** account.
Free + private does not offer branch protection/rulesets, environment secrets, required reviewers, code scanning or
dependency review, and macOS minutes count ×10 against 2,000 minutes per month.

## Decision

### Public repository
The owner made the repository **public** (2026-10-14). It is a reference project, contains no secrets (gitleaks over the
full history), and public repositories get every control above plus unlimited hosted runners — macOS included — for free.
Before publishing, the history was rewritten to the owner's GitHub noreply e-mail and the repository was recreated, so no
earlier commit object remains reachable on GitHub.

### Workflows
- **`ci.yml`** — one quality gate for PRs and `main`, aggregated into a single required check, **`CI result`**. Jobs run
  in parallel (secret scan, workflow lint, lint, Android tests, Android build, iOS tests + build, dependency review).
  Uses no secrets, so Dependabot and fork PRs run the same checks.
- **`deploy-main.yml`** — continuous delivery from trunk to DEV and SIT on every code change to `main`.
- **`release.yml`** — tag `vX.Y.Z` on `main` → STAGE → PROD, each gated by a required reviewer in its GitHub Environment.
- **`store-release.yml`** — manual store upload from a tag; uploads only, a human goes live in the store consoles.
- **`_distribute.yml`** — the one reusable job that runs `fastlane <platform> <beta|release> env:<env>` in the target
  GitHub Environment. All deploy paths share it.

### Trunk and merging
`main` is protected by a ruleset: PR required, `CI result` must pass on the up-to-date branch, linear history,
**rebase-merge only**. Rebase keeps each Conventional Commit with its Jira key on `main` (the commit-msg hook format),
which squash-merge would replace with the PR title. Branches are deleted after merge.

### Supply chain
Third-party actions are allow-listed and **must be pinned to a full commit SHA** (enforced by the repository setting);
CLI tools are downloaded at pinned versions and verified against SHA-256 checksums. `actionlint` and `zizmor` lint the
workflows on every PR. Dependabot updates Gradle, Actions and gems weekly with a 7-day cooldown; Gradle's resolved
dependency graph is submitted so Dependabot alerts and dependency review cover Kotlin libraries.

### Secrets
Environment secrets per GitHub Environment (`dev`, `sit`, `stage`, `prod`); `dev`/`sit` only deploy from `main`,
`stage`/`prod` only from `v*` tags, and only admins can create those tags. The match certificates repo is read through a
**read-only deploy key** instead of a personal access token (no expiry tied to a person, scoped to one repository).

### Runners
GitHub-hosted (`ubuntu-24.04`, `macos-26`). The planned self-hosted Mac (phase 2) is optional and limited to deploy jobs,
switched on by the repository variable `MACOS_RUNNER`; PR code never runs on it.

## Alternatives considered
- **GitHub Pro (private):** branch protection and environment secrets, but no required reviewers (Enterprise only for
  private repositories), code scanning or dependency review, and limited macOS minutes.
- **Squash-merge:** tidier for noisy branches, but loses the per-commit Conventional Commit + Jira key on `main`.
- **Self-hosted Mac for all macOS jobs:** saves no money on a public repository and lets anyone's PR run on the owner's Mac.
- **Personal access token for match:** expires, is tied to a person, and fine-grained tokens are easy to over-scope.
- **One workflow per environment:** duplicated logic; the reusable `_distribute.yml` keeps one code path.

## Consequences
- Logs, artifacts and workflow files are public. Secrets are masked, but steps must never print them; signed builds are
  never uploaded as artifacts.
- GitHub does not let authors approve their own PRs, so the ruleset requires 0 approvals until the AI gets its own
  identity (plan step 8).
- Android DEV/SIT/STAGE uploads are skipped with a warning until Firebase App Distribution is configured (plan step 4).
- Repository settings are code (`.github/settings/`, `scripts/github/configure-repo.sh`) and must be re-applied after
  changing them.
