# Learning guides

Explanatory write-ups for people learning how an enterprise mobile project is set up. Each guide explains **what**
was built in a plan step, **why** it is done that way in a professional team, and what to look at in the code.

They complement, not replace, the reference docs:

| Kind | Where | Answers |
|---|---|---|
| Learning guide | `docs/learning/` | "What is this, and why do enterprise teams do it?" |
| Step log | `docs/log/` | "What happened in step N, what broke, how was it fixed?" |
| ADR | `docs/adr/` | "Which decision was taken, and which alternatives were rejected?" |
| Reference doc | `docs/*.md` | "How do I use / extend this today?" |
